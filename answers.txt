1. Чем git pull отличается от git fetch?

git fetch только скачивает новые коммиты, ветки и теги из удаленного репозитория, не внося никаких изменений в локальную рабочую директорию и текущую ветку. Это позволяет безопасно посмотреть чужие изменения перед их применением.

git pull сначала выполняет git fetch, а затем сразу пытается слить полученные изменения в текущую локальную ветку с помощью merge или rebase.


2. Чем в linux отличается soft link от hard link? Какое поведение будет при удалении файла оригинала? Можно ли создать hardlink на директорию?

Hard link (жесткая ссылка) указывает на тот же самый inode на диске, что и исходный файл. По сути это еще одно имя для тех же данных. При удалении файла оригинала данные с диска не удаляются и остаются доступны по жесткой ссылке до тех пор, пока существует хотя бы одна ссылка на этот inode. Создавать жесткие ссылки на директории в Linux запрещено, чтобы не допустить образования бесконечных циклов в файловой системе.

Soft link (символическая ссылка) — это отдельный файл-указатель, в котором записан путь к целевому объекту. Если удалить оригинал, символическая ссылка останется, но станет нерабочей («битой»). Создавать символические ссылки на директории можно.


3. Как проверить сетевую доступность между двумя linux машинами?

Для проверки базовой доступности узла и маршрута используются утилиты ping и traceroute.

Для проверки доступности конкретного порта используются telnet или netcat (например, nc -zv <ip> <port>), а также curl или wget для проверки веб-сервисов.

На самой целевой машине можно проверить, слушает ли сервис нужный порт, с помощью команд ss -tulpn или netstat -tulpn.


4. На каких компонентах Linux основана контейнеризация в Docker?

Контейнеризация работает за счет встроенных механизмов ядра Linux:

Namespaces обеспечивают изоляцию процессов, сети, файловой системы, точек монтирования и пользователей.

Cgroups (контрольные группы) отвечают за ограничение и учет ресурсов: процессора, оперативной памяти и дискового ввода-вывода.

Слоистые файловые системы (OverlayFS) позволяют объединять неизменяемые слои образа с тонким изменяемым слоем контейнера с помощью механизма Copy-on-Write.


5. Почему вместо "COPY . . / RUN npm install" рекомендуют делать "COPY package.json / RUN npm install / COPY . ."?

Дело в эффективном использовании кэша слоев Docker. Список зависимостей меняется гораздо реже, чем исходный код приложения.

Если скопировать только package.json и запустить установку, этот слой сохранится в кэше. При последующих сборках, если зависимости не менялись, длительный шаг npm install будет браться из кэша за секунду, а заново скопируется только изменившийся код проекта.


6. Могут ли два контейнера внутри одного пода в Kubernetes слушать один и тот же порт?

Нет, не могут.

Все контейнеры одного пода находятся в общем сетевом пространстве имен (Network Namespace) и делят один IP-адрес и пространство портов localhost. Если один контейнер займет порт, второй при попытке занять тот же порт упадет с ошибкой Address already in use.


7. Какие виды JOIN знаете и чем они отличаются?

INNER JOIN возвращает только те строки, для которых нашлось совпадение по условию в обеих таблицах.

LEFT JOIN возвращает все строки из левой таблицы и соответствующие им строки из правой, а при отсутствии совпадения подставляет NULL.

RIGHT JOIN возвращает все строки из правой таблицы и совпадения из левой, подставляя NULL при отсутствии совпадения.

FULL JOIN объединяет результаты левого и правого джойна: возвращает все строки из обеих таблиц, заполняя несовпадающие части значениями NULL.

CROSS JOIN выполняет декартово произведение, соединяя каждую строку первой таблицы с каждой строкой второй таблицы.


8. Что такое having в SQL запросе? Чем отличается от where?

WHERE фильтрует обычные строки таблицы до того, как они объединяются в группы через GROUP BY. В WHERE нельзя использовать агрегатные функции вроде COUNT, SUM или AVG.

HAVING фильтрует уже сгруппированные строки после GROUP BY и используется именно для условий с агрегатными функциями (например, HAVING COUNT(*) > 5).
